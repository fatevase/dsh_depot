# 已安装插件导出设计

日期：2026-10-20，Asia/Shanghai。状态：首版内容范围已确认；已进入实施与原生验收。

## 目标与范围

用户已确认：首版导出插件程序及运行依赖，配置保留在原机。联网机器先按 DSH 原本方式安装插件，管理器再把已安装成品导出；另一台机器使用现有导入和 DSH 安装入口安装。无需网站收录，也不把包上传到网站。

首版提供单插件导出。使用已安装的构建产物，不下载依赖、不运行构建或安装脚本、不要求退出 DSH。只访问所选插件及其运行依赖，不遍历整个 profile 的 node_modules，不备份宿主。批量导出、配置迁移、源码编译、跨平台重编译和自动发布不在首版。

首版兼容范围保守限定为源机系统与架构、记录的 DSH 版本及兼容 Node。含原生模块时还限定源宿主运行时类型、Node ABI 和 Linux libc；不能因为包中只有部分 JS 就声明通用包。导出成功只表示收集、打包与包检查通过，不代表目标机启动验收通过。

## 用户操作

现有“已安装插件”行增加“导出离线包”，保留原来的布局、配色与卸载入口。导出资格与卸载保护分开：宿主内置组件不导出；管理器自身作为普通插件允许导出，其自卸载保护保留。

点击后显示“准备导出 → 收集运行依赖 → 打包 → 检查 → 可下载”，期间可以查看任务或取消。成功卡片显示名称、版本、平台、大小、SHA-256、“本机导出”标记、已排除的内容和迁移限制，提供下载。无需输入 yes，也不出现“退出 DSH”步骤。

输出为标准 npm 布局的 `.tgz`，例如 `free-model-2.5.3-macos-arm64.tgz`。名称不拼完整摘要；摘要存入结果与报告。目标机直接拖入该文件，沿用现有预览与安装流程。

## 程序与配置的边界

- 导出根只能来自当前 DSH 已安装插件清单和服务端解析出的实际包路径，浏览器不提交磁盘路径。
- 收集插件包内程序、静态资源、默认模板及运行依赖。包中已有编译结果按当前字节复制。
- 不读取或归档 DSH 配置、环境变量、登录状态、聊天记录、profile 下的业务数据、pnpm 缓存或整个 store。
- 包内排除 `.env`/`.env.*`、`.npmrc`、`.git`、日志及明确的运行缓存目录；这些排除规则列入报告。若运行文件明确依赖被排除的本机资源，停止并提示配置仍需在目标机准备。
- 无法自动识别被人为写进任意 JS/JSON 程序内容的私有值；本功能保证上述配置边界，不宣称自动清除任意源码中的秘密。自修改插件的程序文件按现状导出，不继承上游原包的校验或验证结论。

## 依赖收集

1. 只接受当前清单中 `installed` 且能解析真实 package.json 的顶层 DSH bundle。包名、实际版本、DSH patch 和入口文件都需核对。
2. 从每个实际包目录按 Node 的解析位置寻找其 dependencies、optionalDependencies，保留 pnpm 虚拟 store 中的真实路径和 peer 上下文。不要把全部依赖摊平成同一层，也不要按名字全局去重。
3. 将实际运行依赖复制为包内物理目录；根和子包原有 node_modules 均不直接整目录复制。相同名字的不同版本分别放在对应父包的 node_modules 中。devDependencies 不加入收集入口。
4. `file:`、`link:`、`workspace:`、Git 来源如已落为可定位、具有合法版本的实际包，可复制并改写为实际版本；npm alias 保留别名与实际包名的关系。不能留下指向原机器的绝对路径或包外链接。
5. 依赖图以真实包路径辨认实例；祖先链发现环时首版明确阻止导出，返回 `DEPENDENCY_CYCLE_UNSUPPORTED`，不无限递归、不悄悄漏包。后续若支持包内链接，须先通过原版 DSH 安装验证。
6. 必需依赖缺失、版本与声明不匹配、资产链接越出允许的包范围，均阻止导出。可选依赖缺失可记录为源机原本缺失，不临时补装，也不推断可用于其他平台。
7. DSH 核心模块由目标宿主提供，保留为 host peer；不能把另一套 DSH 塞进包。普通第三方 peer 必须能够确定由兼容宿主提供，否则首版阻止并说明未确认的 peer，不随意复制另一份 React 等共享实例。
8. 宿主核心身份不能仅以 `@deepseek-ai/` 命名空间判断。现有导入检查对此过宽，需同步收敛为明确的 DSH 核心模块判断；同组织的普通运行库仍按运行依赖处理，防止本机导出后反被导入检查误拒绝。

Python 虚拟环境、系统命令、外部浏览器、驱动和模型文件不等同于 Node dependencies。若实际内容或插件声明揭示此类要求，报告其依赖项与限制；不能声称这些资源已经被自动完整迁移。

## 打包与检查

导出在管理器自己的 staging 目录中完成，源插件和宿主 manifest、锁文件、store 均不修改。保留原包必要的发布信息；移除 devDependencies，禁用安装生命周期脚本，按收集结果更新依赖声明及 bundleDependencies。运行时需要的普通 scripts 不因打包而一并删除。

使用现有 tar 库生成 `package/` 根归档，不调用 npm/pnpm pack，避免依赖额外工具和隐式执行脚本。重新生成 depot-manifest.json、depot-files.json；旧的公开校验与验证记录不能直接复用。

元数据 source 标记 `local-export`，只记录包身份与源宿主兼容信息，不把本机绝对路径写进公开包。源环境与 testedEnvironments 区分：源机当前运行信息不是新导出包的验证证据，导出包的 testedEnvironments 应为空。保留 schemaVersion=1，增量字段向后兼容。

完成后用现有 inspectArtifact 解包检查实际归档，核对文件完整性、依赖完整性、DSH 声明、入口和平台限制。只有实际归档检查通过才能转入 ready。导入界面显示“本机导出，目标环境尚未验证”，不提升为网站公开验收通过。

## 任务与下载接口

导出任务独立于安装任务状态机，放在当前 host 的 `exports/<exportId>/`。状态为 `queued / collecting / packing / checking / ready / failed / cancelled`。记录 ownerId、hostId、源包身份与指纹、阶段、大小、错误和结果摘要；公开响应不含源磁盘路径。

- `exports.create({packageName, installedFingerprint}) → {exportId, state}`：核对当前插件身份与指纹，创建任务并放入有界后台队列。
- `exports.list() → ExportSummary[]`、`exports.status({exportId}) → ExportSummary`。
- `exports.cancel({exportId}) → ExportSummary`：取消后清理未完成产物，不影响源插件。
- `GET /api/depot/export-download?id=<exportId>`：通过现有 connection 鉴权，仅当前 host/owner 的 ready 任务可下载；以文件流返回，不先把整个包读进内存。

每个 host 同时最多执行一个导出任务；下载和导出不能阻塞 DSH 主线程。任务遇到进程重启时，未完成项标为中断失败，用户可重新导出，不增加复杂恢复协议。ready 下载保留 24 小时；下载中的文件不清理。失败和取消的 staging 清理，任务摘要保留最近 20 条。生命周期监听与队列随管理插件 dispose 结束。

沿用当前上限：展开总量 2 GiB、压缩包 512 MiB、100000 项、深度 64。按任务累计预算，中途超限立即停止，而不是复制完才发现超限。仅对实际复制的文件记录状态，若导出期间源文件、包身份或所选依赖图发生变化，返回 `SOURCE_CHANGED`，不宣称一致快照。生成包前后重新核对选中依赖的身份；不为此扫描无关插件。

## 验收

- 平铺 npm 与 pnpm 外链布局都可导出，依赖在归档内可独立解析。
- 多版本、npm alias、本地已安装 workspace 包、缺失可选依赖有对应真实测试；环与未确认 peer 有明确失败结果。
- `.env`、profile 配置和业务数据不进入导出包，源目录与配置不发生写入；包外资产链接不被跟随。
- 取消、超限、源变化、下载越权、任务中断均有明确状态，内存使用不随包大小线性增长。
- 本机导出包通过现有导入检查；在同平台独立的原版 DSH 空 profile 中安装并验证声明的注册项，确认不需重编译或联网补依赖。若原版 DSH 仍尝试外部解析，必须记录失败并修复打包方式，不能只依靠 inspect 通过就宣称迁移成功。
- Windows、macOS、Linux 在原生 Actions runner 上执行收集、导出、重新导入的回归；真实 Desktop 测试继续仅对已适配的 macOS 0.12.0 开放。

## 明确不变的内容

不更改网站分类、目标平台标识或现有页面设计；不接入 Agent/LLM，不新增随包 npm/pnpm，不改变 DSH 自身安装策略。新增功能只提供来源明确的可迁移本机成品。
