# DSH Depot 仓库模块边界

用户已确认同仓库拆分 web、plugins 和 distribution，并要求同步做好 Git、命令、Actions、文档和验证；沿用当前会话直接实现的方式。

- `web/`：保留现有 Svelte 页面、样式、URL、分类与平台交互；独立构建，只消费 catalog.json 和 manager-catalog.json。无网络的本地构建默认生成真实空目录，也可输入已发布目录。
- `plugins/dsh-depot-manager/`：管理器的宿主插件、Svelte 管理页、核心、维护脚本、插件及安装包构建器和对应测试。成品仍为标准 DSH 插件与现有三平台脚本归档。
- `distribution/`：规则发现、recipes、状态、平台构建、OS 隔离验证和发布。管理器 CI 验证/发布编排仍由此处管理，不能进入插件运行时依赖。
- `packages/offline-format/`：现有平台标识、下载状态、文件清单和完整性规则，以及管理器发布资格的纯判断。无外部依赖，不依赖网站、插件或流水线。
- 使用 npm workspaces 和根目录唯一 package-lock.json。各模块声明自己的构建依赖和测试命令，不引入新的桌面或安装框架。
- 三条工作流分别负责网站、管理器归档、普通插件分发。网站源码修改不触发插件编译；管理器修改不触发普通插件编译。已发布目录变化通过默认分支上受限的 workflow_run 触发网站刷新，不使用上游未信任的代码或制品。
- Pages 仅由网站工作流部署；PR 只有构建/测试权限。管理器正式发布仍必须满足原有精确字节验收，普通插件既有未验证发布策略保持不变。
- Git 保留源码/配置/文档；归档仍放 Actions/Release。沿用草稿 PR #9，不合并、不发布、不部署；此前本机轻量包试验记录一并同步。

验收：原测试全部迁移保留；分别运行模块测试，冷安装依赖、构建网站、构建管理器轻量包并在独立 DSH 配置中完成安装与宿主加载。核对页面源文件内容未变、没有旧源码路径、工作流路径过滤和发布权限正确。三平台归档重建仍绑定新字节，局部本机证据不会替代完整原生矩阵。
