# DSH 离线插件管理器

在当前 DSH Web 环境中导入已构建的 `.tgz` 或成品目录，检查依赖与平台后直接调用 DSH 安装；安装完成后重启 DSH。

管理页面显示安装预览、插件列表与任务记录。卸载默认保留业务数据与配置，内置项和管理器本身受保护。管理器更新或移除请从外部脚本进行，完成后重启 DSH。

首次使用需要已有的 DSH。完整安装包附带独立 Node，轻量包需要 Node `^22.19.0 || >=24.0.0`。不需要管理员权限，不会下载运行依赖，不执行包的安装脚本。原生模块仍须适配目标宿主。

“等待加载”表示文件操作已完成；只有宿主观察到相应插件实际加载后才显示“已加载”。常规安装直接调用对应 DSH，不遍历或备份整个已安装依赖目录，不自动回滚。失败时查看任务错误和日志，修正后重装成品或先前版本；旧版已创建的恢复点仍可从外部脚本恢复。

当前版本针对 DSH `0.2.0-rc.2` Web 公开接口开发。官方桌面宿主尚未验证写入能力时会阻止修改。各平台实际可用范围以分发报告为准。

## 把已安装插件带到另一台机器

1. 在联网机器先按 DSH 的正常方式安装插件，并确认插件能够运行。
2. 打开“离线插件”，在“已安装插件”找到所需插件，点击“导出离线包”。不需要退出 DSH。
3. 在“本机导出”查看进度。完成后下载 `.tgz`，同时保存显示的 SHA-256；下载保留 24 小时。
4. 把文件带到相同系统、架构及兼容 DSH 的目标机器，拖入管理器，查看提示后安装，完成后重启 DSH。
5. 在目标机另行配置账号和外部服务，检查插件入口与实际功能。

导出范围是当前插件程序和声明的运行依赖；不读取 DSH 配置、登录状态、聊天记录或 profile 数据。包内的 `.env`、`.env.*`、`.npmrc`、Git、日志和缓存会排除，清单可在结果中查看。无法识别被直接写入任意 JS/JSON 程序的私有值；分发自定义程序前请自行确认。

导出不会下载、编译或运行安装脚本，也不会修改源插件。管理器自身可导出，内置 DSH 核心由目标宿主提供。原生模块按源平台、运行时类型、Node ABI 和 Linux libc 保守限制。系统命令、Python 环境、浏览器、驱动和模型需另行准备。导出成功表示归档检查通过，不能替代目标机器的实际启动验证。

遇到 `MISSING_DEPENDENCY` 请在源环境修复插件；`PEER_UNCONFIRMED` 表示无法确认共享依赖；`DEPENDENCY_CYCLE_UNSUPPORTED` 表示首版暂不支持该依赖环。`SOURCE_CHANGED` 表示导出期间程序发生变化，等待更新完成后重试。取消或失败不会移除源插件；进程退出时未完成导出标记失败，重新导出即可。
